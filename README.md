## How the five techniques fit together

```
                       ┌────────────── Genetic Algorithm (genetic.py) ──────────────┐
                       │  evolves: piece values, mobility weight, NN-blend weight   │
                       ▼                                                            │
 board ─► Minimax + Alpha-Beta (search.py) ─► calls Evaluator at leaf nodes ◄── fitness = match results
          + MVV-LVA move ordering             (evaluator.py)
          + quiescence search                   score = (1-w)·Heuristic + w·NeuralNet + w_mob·FuzzyActivity·Mobility
          [Heuristic + Adversarial]               │            │               │
                                       material + PST   neural.py        fuzzy.py
                                       (hand-crafted)   773→16→1 MLP     Mamdani FIS
                                                        backprop         (material, phase) → activity
```

| Technique | File | What it does in the engine |
|---|---|---|
| **Heuristic search** | `evaluator.py`, `search.py` | Material + piece-square-table evaluation; MVV-LVA move-ordering heuristic; quiescence search |
| **Adversarial search** | `search.py` | Minimax with alpha-beta pruning (White = MAX, Black = MIN) |
| **Neural network** | `neural.py` | 773→16→1 MLP written in NumPy; trained with backpropagation to predict search-based position values |
| **Fuzzy logic** | `fuzzy.py` | Mamdani fuzzy system: inputs *material balance* and *game phase* → output *activity* that scales the mobility bonus |
| **Genetic algorithm** | `genetic.py` | Evolves 6 evaluation parameters; fitness = results of games vs a fixed baseline |

### Reasoning for every AI move (both modes)
After each AI move the terminal prints, and the browser shows, a short explanation specific to that move:

```
Move 3 | AI (White) plays Nc3
  Why      : develops the knight off the back rank to the centre
  Think    : looked 3 half-moves ahead ... searched 7,294 positions; alpha-beta made 208 cut-offs ...
  Plan     : expects  Nc3  Qf6  d4
  Score    : slightly better for the AI (+0.86 pawns, White's view)
  Based on : heuristic +0.50; neural net +0.77 (trusted 20%); fuzzy logic: opening + equal material -> high piece activity (0.84)
  Others   : d4 (no better than +0.86); h3 (no better than +0.86)
```
*Why* is generated by checking the real position (captures, checks, threats, development, escapes, castling, promotion...); *Plan* is the principal variation the search found; *Others* are the runner-up moves and the best score they could reach.

## Viva preparation (likely questions)

**Adversarial search / heuristic search**
1. *Why minimax?* Chess is a two-player, zero-sum, perfect-information game. MAX (White) picks the child with the highest value, MIN (Black) the lowest; values come from the evaluation function at depth limit.
2. *What does alpha-beta do?* Keeps α (best value MAX can already guarantee) and β (best MIN can guarantee). When α ≥ β the remaining siblings can't change the result, so they are skipped. It returns the **same value** as plain minimax (shown in `benchmark.py`) with far fewer nodes: best case O(b^(d/2)) vs O(b^d).
3. *Why move ordering?* Alpha-beta prunes most when the best move is searched first. MVV-LVA tries "capture a valuable piece with a cheap piece" first.
4. *What is the horizon effect / quiescence?* At the depth limit a queen may be "captured" while a recapture is pending. Quiescence continues with captures only until the position is quiet.
5. *What is the heuristic?* h(n) = material + piece-square bonuses (e.g. knights are better in the centre). It is not admissible/A\*-style cost; it estimates *goodness* of a state, not distance to a goal.
6. *Complexity?* Branching factor ≈ 30–35; depth 3 plain minimax ≈ 30³ ≈ 27k nodes. This is why pruning matters.

**Neural network**
7. *Architecture?* 773 inputs (768 piece-on-square one-hot + 5 material-difference inputs) → 16 tanh hidden → 1 tanh output.
8. *Training?* Supervised regression. Target = tanh(quiescence-search value / 400). Loss = MSE. Forward pass, **backpropagation** of dL/dy through the tanh units (chain rule, see `backward()`), mini-batch gradient descent, L2 weight decay.
9. *Over-fitting?* First attempt (2,700 samples) had validation error ≈ target variance. Fixed with more data (10,800 via colour-mirror augmentation), a smaller hidden layer and weight decay.
10. *Why blend with the heuristic instead of using the NN alone?* The tiny NN is only moderately accurate (validation MSE ≈ 0.23 vs target variance 0.49), so the GA decides how much to trust it.
11. *Why tanh?* Bounded, smooth, zero-centred; derivative is 1−tanh².

**Fuzzy logic**
12. *Why fuzzy here?* "Winning", "endgame" are vague concepts with no sharp boundary; fuzzy sets let rules blend smoothly instead of switching abruptly.
13. *Walk through the pipeline.* Fuzzify (triangular/shoulder membership) → apply rules with AND=min → aggregate with OR=max → defuzzify with centroid. Example: equal material in the opening fires "opening → high activity", output ≈ 0.84.
14. *Mamdani vs Sugeno?* Mamdani has fuzzy output sets (used here); Sugeno uses crisp output functions.

**Genetic algorithm**
15. *Encoding?* Real-valued chromosome of 6 genes, each bounded.
16. *Fitness?* Score in games against a fixed baseline engine, both colours, same random opening (+ small material tie-breaker).
17. *Operators?* Tournament selection (k=3), blend crossover, Gaussian mutation, elitism (best 2 kept so fitness never drops).
18. *Limitations?* Small population/few games ⇒ noisy fitness. My GA over-fitted its training games: the evolved genes lost on unseen openings, so a validation step rejected them. That is the key lesson: always test evolved parameters on held-out data.

**General**
19. *Why not just use Stockfish-style NNUE?* Course-level project: every component is implemented from scratch/explained, not a black box.
20. *Possible improvements:* transposition tables, iterative deepening, opening book, deeper/larger NN trained on real games, Sugeno fuzzy king-safety.

## Results (measured - see `benchmark.py`, `ga_train.log`, `nn_train.log`)

**Alpha-beta vs minimax** (identical best move and value every time):

| Position | Depth | Minimax nodes | + Alpha-beta | + Move ordering |
|---|---|---|---|---|
| Start | 2 | 877 | 324 | 324 |
| Start | 3 | 21,699 | 3,200 | 3,165 |
| Middlegame | 2 | 162,536 | 4,116 | 2,973 |

**Neural network** (773 inputs: 768 piece-on-square + 5 material-difference inputs; 16 hidden; 10,800 positions with colour-mirror augmentation): validation MSE 0.230 (target variance 0.488). Adding the material inputs cut the validation error from 0.315.

**Genetic algorithm** (population 6, 3 generations, 6 games per candidate): training fitness rose from an average of +0.14 to +2.86 (best +4.30). On *unseen* openings the evolved genes scored -3.28 against -1.04 for the seed individual, so the validation step rejected them: they had over-fitted the training games. An earlier, looser GA run behaved the same way (it lost 0-6 to the baseline). Final parameters are therefore the standard piece values with `w_mob = 3.0`; the neural-net blend `w_nn = 0.1` came from an 8-game ablation (net weight 0%: 3W-1L-4D, 10%: 5W-2L-1D, 20%: 3W-4L-1D, 30%: 3W-3L-2D; see `best_params.json`).

**Match results (depth 2, 8 fresh openings, adjudicated on material after 80 plies):** Baseline vs Random: 4-0-0. Full AI vs Baseline: 1 win, 4 losses, 3 draws.

**Honest reading - the baseline (material + piece-square tables + search) is already a strong engine for its depth. The full engine's extra components - a small net trained on that same heuristic's values, fuzzy-weighted mobility, and GA tuning - did **not** produce a measurable improvement in these small matches, and the net's value is limited because it learns from the heuristic itself. With 8 games per test the results are noisy, so the right conclusion is "no demonstrated gain", not "worse" or "better". The project demonstrates how each technique is implemented and integrated, and the GA's validation step shows why evolved parameters must be tested on unseen data.
